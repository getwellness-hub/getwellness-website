# Security Rules

## Purpose

Keep the website, repository, users and content protected from avoidable security problems.

## Rules

1. Never expose passwords, API keys, tokens, private keys or other secrets.
2. Never place sensitive credentials directly inside HTML, CSS, JavaScript or public files.
3. Do not collect unnecessary personal information from visitors.
4. Do not add third-party scripts, trackers or services without checking their purpose and privacy impact.
5. Keep contact forms and user-input features protected against basic abuse.
6. Never add suspicious, malicious or unauthorized code.
7. Do not introduce downloads or external files that may harm users.
8. Preserve existing security-related settings unless a change is explicitly required.
9. Check external links before adding them to important pages.
10. If a security issue is discovered, stop unnecessary changes and fix the issue before continuing.

## Privacy

The website should follow a privacy-conscious approach and avoid collecting information that is not necessary for its educational purpose.

## Repository Safety

Never expose private repository information, credentials or secrets through public commits.

## Change Safety

Before adding new scripts, integrations or external services, inspect their purpose and confirm that they are appropriate for the website.

## Final Check

After security-related changes:

- Check the website loads correctly.
- Check existing images remain intact.
- Check existing links continue to work.
- Check no secret or private information was added.
