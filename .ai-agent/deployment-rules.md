# Deployment Rules

## Purpose

Keep the live website stable, functional and safe when changes are published.

## Rules

1. Make changes only after checking the existing website structure.
2. Do not deploy untested or incomplete changes.
3. Preserve the existing GitHub Pages configuration.
4. Keep the main branch stable.
5. Never delete or rename existing website assets during deployment.
6. Existing logo and image filenames must remain unchanged.
7. Existing article URLs should remain functional.
8. Check index.html after important changes.
9. Verify CSS and JavaScript functionality after deployment.
10. Verify sitemap.xml and robots.txt remain available.
11. Check important internal links after deployment.
12. Confirm that the live website loads correctly on mobile and desktop.
13. If a deployment causes a problem, stop further changes and restore the last working version.
14. Do not make multiple unrelated changes in a single deployment.
15. Prefer small, controlled and reversible deployments.

## Pre-Deployment Checklist

Before publishing:

- Check HTML structure.
- Check navigation.
- Check images.
- Check logo.
- Check article links.
- Check search functionality.
- Check responsive layout.
- Check SEO metadata.
- Check sitemap.xml.
- Check robots.txt.
- Check for accidental file deletion or renaming.

## Post-Deployment Checklist

After publishing:

- Open the live homepage.
- Confirm the logo is visible.
- Confirm the hero image is visible.
- Confirm existing article images are visible.
- Test important article links.
- Test navigation.
- Test search.
- Check mobile layout.
- Check that no existing content disappeared.

## Rollback

If the live website becomes broken after deployment:

1. Stop making additional changes.
2. Identify the last known working version.
3. Restore that version.
4. Verify the live website again.
5. Only then investigate and make another controlled change.

## Final Principle

Website stability and preservation of existing working content take priority over unnecessary changes.
